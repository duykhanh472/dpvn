# Logging and observability

The service writes structured logs to **stdout** and never to files inside the
container. The platform (Docker, systemd, Kubernetes) owns rotation and
shipping.

## 1. Formats

| `DP_LOG_FORMAT` | Output | When |
|---|---|---|
| unset / `text` | human-readable `tracing` lines | local development |
| `json` | one JSON object per line | production (set in the image) |

Production images default to `DP_LOG_FORMAT=json` (see `Dockerfile`).

A request line looks like this:

```json
{"timestamp":"2026-01-01T03:15:00.123456Z","level":"INFO","fields":{"message":"request completed","request_id":"6f1c...","method":"POST","path":"/projects/42/pages/7/save","status":200,"duration_ms":41.2},"target":"dp_web::middleware::access_log"}
```

Health probes (`/healthz`, `/readyz`) are intentionally not logged to avoid
noise; their failures are logged by the handlers themselves.

## 2. `RUST_LOG` guidance

`RUST_LOG` uses `tracing-subscriber`'s `EnvFilter` syntax:
`target=level,target=level`, with `,` separating directives.

| Situation | Value |
|---|---|
| Production default | `info,dp_web=info,dp_db=warn` |
| Investigating a request | `info,dp_web=debug,dp_db=warn` |
| Investigating SQL timing | `info,dp_web=debug,dp_db=debug` |
| Very noisy incident | `warn,dp_web=info` |
| Silence dependencies | `info,hyper=warn,sqlx=warn` |

Rules:

- Never set `trace` in production for more than a few minutes; it is expensive
  and can leak page text through debug spans.
- Prefer per-target overrides (`dp_web=debug`) over a global `debug`.
- Changing `RUST_LOG` requires a restart (or a container recreate).

## 3. What is never logged

The code is written so that these never reach a log line:

- passwords and password hashes
- session tokens and CSRF tokens
- activation tokens
- email bodies
- full page text (wordcheck logs counts and words, not the page)
- `AppConfig` (its `Debug` impl redacts the database and mail URLs)

If you add a log line, log identifiers and counts, not payloads.

## 4. Rotation

### Docker (compose)

Both compose files configure the `json-file` driver:

```yaml
logging:
  driver: json-file
  options:
    max-size: "10m"
    max-file: "5"
```

That caps each container at 50 MB. For a central stack, switch to the
`journald` or `fluentd` driver and let the platform rotate.

### systemd (binary install)

```ini
[Service]
StandardOutput=journal
StandardError=journal
Environment=RUST_LOG=info,dp_web=info,dp_db=warn
Environment=DP_LOG_FORMAT=json
```

`journald` rotates automatically (`SystemMaxUse=` in `journald.conf`). Query
with `journalctl -u dproofreaders -f -o json`.

### logrotate (file install, not recommended)

If you must write to a file, rotate with:

```
/var/log/dproofreaders/*.log {
    daily
    rotate 14
    compress
    missingok
    notifempty
    copytruncate
}
```

## 5. Minimum alerts

| Signal | Threshold | Source |
|---|---|---|
| 5xx rate | > 1% for 5 min | access log `status` field |
| p95 save latency | > 500 ms for 10 min | `duration_ms` where `path` ends in `/save` |
| DB pool saturation | > 90% for 5 min | `sqlx` pool metrics / DB `Threads_connected` |
| Disk on data volume | > 80% | host/volume exporter |
| Stale-claim job | no `released stale page claims` line in 30 min | `dp prune` logs |
| `readyz` failing | 2 consecutive checks | probe |
| Backup age | newest `db-*.sql.gz` older than 26 h | backup directory |

## 6. Correlating a user report with logs

Every response carries `X-Request-Id` (generated by the app or supplied by
nginx as `$request_id`). Ask the user for the value shown by their browser's
network panel, then:

```sh
docker compose -f docker-compose.prod.yml logs app | grep '"request_id":"<id>"'
```

The access log line includes method, path, status, and duration. Error lines
from the same request include the full source chain.
